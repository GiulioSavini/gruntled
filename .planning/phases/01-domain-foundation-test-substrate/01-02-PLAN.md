Facts verified by the planner on go1.27.0. These correct RESEARCH.md §Pattern 1, whose example commands have three bugs:
1. External test packages (`package foo_test`) list their imports in `.XTestImports`, NOT `.TestImports`. The research command reads only Imports and TestImports, so a `repograph_test` file importing `os` would pass. The check MUST read `.XTestImports` too.
2. `go list` exits 0 on a Go syntax error and does not report it in `.Error` (verified: a file containing `func {` gives rc=0). With `found=$(go list … | grep … || true)`, broken domain code would therefore pass silently. The script MUST start with a compile gate, `go vet ./internal/domain/... ./cmd/...`, which exits 1 on syntax and type errors.
3. The `go list -deps -test` output includes test variants shaped like `github.com/GiulioSavini/gruntled/internal/domain/a.test` and `…/domain/a_test [github.com/GiulioSavini/gruntled/internal/domain/a.test]`. A non-domain package pulled in by a domain test appears under its plain path. A prefix-anchored allowlist (`^<module>/internal/domain/`) is therefore correct; a substring match (`grep -F`) is not.

Decision: the transitive rule is an ALLOWLIST. Every non-stdlib dependency must match `^github\.com/GiulioSavini/gruntled/internal/domain/`. This strictly subsumes the locked blacklist (hcl, terraform-config-inspect, go-getter, fsnotify) and also catches imports of other internal layers. It is noted as fulfilling the locked ARCH-01 decision. Print the named libraries in the failure message so the intent is obvious.

Decision: CI has 2 jobs, not the 4 in RESEARCH.md. `check` runs gofmt, vet, build and test as separate steps, each able to fail. `architecture` runs the check script and its self-test. This follows the user's rule of few jobs, each able to genuinely fail. build and vet are not worth separate jobs.

  <files>scripts/check-architecture.sh, scripts/test-check-architecture.sh</files>
  <action>
    Create `scripts/check-architecture.sh` (bash, chmod +x). It starts with `set -euo pipefail` and `cd "$(dirname "$0")/.."`, so it always runs from the root of whatever tree contains it. That is what makes the self-test's throwaway copies work.

    Steps, in order. Collect every failure, print one labelled block per failing rule to stderr, and exit 1 if any rule failed:
    0. Compile gate: `go vet ./internal/domain/... ./cmd/...`. On failure, print "domain or cmd does not compile" and exit 1 immediately.
    1. Non-vacuous guard: `pkgs=$(go list ./internal/domain/...)`. Require at least 2 lines; fewer means the check is looking at the wrong path, so fail.
    2. Rule "domain-direct-io": `go list -f '{{range .Imports}}{{.}}{{"\n"}}{{end}}{{range .TestImports}}{{.}}{{"\n"}}{{end}}{{range .XTestImports}}{{.}}{{"\n"}}{{end}}' ./internal/domain/...`, captured into a variable FIRST so a go list failure trips `set -e`. Then `sort -u | grep -E '^(os|os/.+|io/fs|io/ioutil|path/filepath|net|net/.+|syscall)$' || true`. Any match is a failure.
    3. Rule "domain-external-deps": `module=$(go list -m)`, then `module_re=$(printf '%s' "$module" | sed 's/[.]/\\./g')`. Capture `go list -deps -test -f '{{if not .Standard}}{{.ImportPath}}{{end}}' ./internal/domain/...` into a variable, then filter it with `grep -v '^$' | grep -v -E "^${module_re}/internal/domain/" || true`. Anything left is a failure. The message names hcl, terraform-config-inspect, go-getter and fsnotify as examples of what the domain must never reach.
    4. Rule "binary-links-testsupport": capture `go list -deps -f '{{.ImportPath}}' ./cmd/gruntled`, then `grep -E "^${module_re}/internal/testsupport(/|$)" || true`. Any match is a failure, because the shipped binary must never link test support (CONTEXT.md).
    On success, print `architecture: OK (<n> domain packages)` to stdout.

    Create `scripts/test-check-architecture.sh` (bash, chmod +x, `set -euo pipefail`, `cd` to the repo root). Define `mkcopy()`, which does `d=$(mktemp -d)`, copies `go.mod`, `go.sum` (only if present), `cmd`, `internal` and `scripts` into it with `cp -R`, and echoes the path. Register every copy in a `trap … EXIT` cleanup. The working tree is NEVER modified.

    Cases. Each one runs `bash "$copy/scripts/check-architecture.sh"` and asserts the exit code, printing `PASS <case>` or `FAIL <case>` and exiting 1 on any unexpected result:
    - clean: an unmodified copy exits 0.
    - direct-os: add `internal/domain/repograph/zz_probe.go` containing `package repograph` and `import _ "os"`. Expect non-zero.
    - xtest-os: add `internal/domain/repograph/zz_probe_test.go` containing `package repograph_test`, `import _ "os"` and `import "testing"`, plus `func TestZZProbe(t *testing.T) {}`. Expect non-zero. This case proves the XTestImports fix.

    - testsupport-linked: create `internal/testsupport/zzprobe/p.go` and `cmd/gruntled/zz_probe.go` (`package main`, `import _ ".../internal/testsupport/zzprobe"`). Expect non-zero.
    - vacuous: `rm -rf "$copy/internal/domain"`. Expect non-zero.
    Finish with `all architecture self-tests passed`.

    Run both scripts locally. Confirm `git status --porcelain` is empty apart from the two new scripts, which proves the self-test did not dirty the tree. Commit with `ci(01-02): add architecture check and self-test` and push.
