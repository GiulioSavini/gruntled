The contract (identical in 03-02 and 03-03). Document it verbatim.

Usage text printed by `gruntled check -h`, to stderr, exit 0:
```
usage: gruntled check [--format text|json] [path]

Check the Terragrunt repository at path (default ".") for dependency
output references that name an output the target module does not declare.
Flags may appear before or after path; "--" ends flag parsing.

Flags:
  --format text|json   output format (default "text")

Exit codes:
  0  analysis completed, no error diagnostics
  1  analysis completed, at least one error diagnostic (GRT001, GRT100)
  2  usage error: unknown command or flag, invalid --format, more than one path
  3  analysis could not run: path missing, not a directory or unreadable, or an internal failure
```

Text format (stdout, one line per diagnostic, canonical order): `path:line:col: CODE message`, followed by ` (unit U)` when the diagnostic belongs to a unit. Columns are 1-based byte columns. Paths are repo-relative and always use `/`. The summary goes to stderr: `gruntled: checked N units (K unknown): E errors, W warnings`, or `gruntled: no Terragrunt units found`.

JSON format (stdout, a single document, schema version 1). There is no stderr summary in JSON mode.
Top-level keys: `version`, `diagnostics`, `unknown_units`, `unknown_modules`, `summary`.
- `diagnostics[]`: `code`, `severity`, `file`, `line`, `column`, `unit` (omitted for file-level diagnostics), `message`.
- `unknown_units[]`: `path`, `status` (module-unknown or config-unknown), `reason`.
- `unknown_modules[]`: `path`, `reason`.
- `summary`: `units`, `resolved`, `module_unknown`, `config_unknown`, `unknown_modules`, `errors`, `warnings`.
Empty lists print as `[]`. HTML characters are not escaped.

GRT001 message: `dependency "<label>" output "<Y>" is not declared by module "<module>" (target unit "<target>")`, plus the suffix `; mock_outputs supplies it, so apply would silently use the mock value` only when masking is certain.

    4. **Diagnostics**:
       - GRT001: what it means, and the two-hop resolution in one paragraph.
       - GRT100: HCL syntax error, one per file, first error only, byte column.
       - Every other code is reserved for the future (GRT002-006).
    5. **How GRT001 treats mock_outputs, enabled and skip_outputs (DIAG-03)**:
       - The decision table from 03-RESEARCH.md Pattern 1, rows 1-7, reworded for users. Rows 1-5 are silent (undeclared label, `enabled` not literally true, `skip_outputs` not literally false, target unresolved or not a unit, target module or surface unknown). Row 6 is declared, so nothing is reported. Row 7 is GRT001 at error.
       - The rule: mock_outputs never suppresses and never downgrades GRT001. Reason: with merge-with-state (or a module with zero outputs), Terragrunt's `apply` fills the removed output with the mock value, so production silently gets a mock. That is exactly the bug gruntled exists to catch. Without a mock covering it, `apply` fails. Both are bugs.
       - When the suffix appears: mock keys literally include the output, `apply` is literally allowed (an absent list or a literal empty list both mean every command), and merge-with-state is literally on or the target module declares zero outputs. Any non-literal fact drops the suffix and never changes whether GRT001 fires.
       - `mock_outputs_merge_strategy_with_state`, when present, takes precedence over the deprecated `mock_outputs_merge_with_state`, as in Terragrunt.
       - Rejected alternatives: **suppress** (it hides the worst variant, a silent mock value in production, and makes the Phase 4 mutation experiment impossible on the primary corpus, where every reference has this shape) and **downgrade to warning** (warnings exit 0, so CI would pass a repository that deploys mock values).
       - Other silences that come from the graph, not the analyzer (unknown units, lazily evaluated positions such as ternary branches and `try()`, stack targets, include-target units), with a one-line pointer that they are handled at graph construction.
    6. **Guarantees**:
       - Determinism: identical bytes and exit code from any checkout path; paths are always repo-relative.
       - No network and no external processes: the binary links no `net`, `os/exec`, `plugin` or `crypto/tls` package, enforced by the `binary-no-net-no-exec` rule in scripts/check-architecture.sh.
       - No writes: the repository is opened read-only through `os.Root`, proven by a test that runs on a read-only tree.
       - No cache, no telemetry.
    7. **Known limitations**:
       - A diagnostic's identity includes its position, so a line shift changes it.
       - Ungenerated Terragrunt stacks are invisible.
       - Undeclared dependency labels and cycles are not reported in v0.1.

    Keep it under roughly 250 lines.
