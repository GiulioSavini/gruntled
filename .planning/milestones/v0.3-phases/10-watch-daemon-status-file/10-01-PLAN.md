Extend the binary-no-net-no-exec proof (Step 9) BEFORE fsnotify is added, so the commit that later runs `go get fsnotify` (plan 10-05) can never turn CI red.

Why this is needed (measured in research): once fsnotify is linked on linux/darwin, `golang.org/x/sys@v0.46.0/unix/syscall_unix.go:582` (`unix.Exec` calling `syscall.Exec`) matches the textual spawner regex on 4 of 6 targets, although the linker removes that code as unreachable.

Why the guarantee is NOT weakened (state this in the script comment block): the textual scan is a grep with documented gaps (aliased imports, dot imports, x/sys spawners, reflection). It is replaced for exactly one package (golang.org/x/sys/unix, exempt by import path) and complemented for ALL packages by a linker-level check on the real built binary per target. `go tool nm` lists what is actually linked, including std and every third-party package, regardless of how it is spelled in source, so it closes the aliased/dot-import/x/sys gaps the grep could never close. The import deny-list half is unchanged. Net result: every case the old proof caught is still caught (import list, plain-spelled spawners in any non-x/sys/unix file), plus cases it missed.
